# 出牌计分预估设计

状态：历史设计；2026-10-13 已断开 MCP 自动评分接入，观察不再返回 `plays` 或生成实机评分快照。独立沙盒 API 保留；同一快照导出现在只由按需的 `game_analyze` 使用，见 `game-analyze-design.md`。以下记录原设计。

## 数据流

`score_snapshot.lua` 只读取当前局面，随 bridge 观察传给服务端。
`play/client.ts` 验证内部快照，只在需要 `plays` 时调用常驻 `ScoringSandbox.plays`。
局面加载、组合枚举、计分、全局前 15 名排序和行格式全部封装在 `env/sandbox` 内。
原来的游戏内影子计分已经移除。

快照包含卡牌当前 base/ability/edition、Joker 成长值、牌型等级和出牌历史、
钱、概率、Boss 记忆、牌背配置，以及手牌、抽牌堆和弃牌堆的完整成员。
成员缺失、未知原型或无法序列化的数据显式返回 `unavailable`。
抽牌堆按内容排序，不传抽牌顺序；种子和实机 RNG 流不导出。
手牌、Joker 或消耗品存在背面牌时，在读取其身份前停止构造快照。

实机快照标记 `passiveEffectsApplied: true`，worker 使用已生效的概率、槽位、
debuff 和卡牌数值，不重复执行 Joker 的 `add_to_deck` 或每帧更新。
普通离线调用继续按沙盒 README 的输入基值约定运行。

## 枚举与输出

在沙盒内枚举当前手牌 1–5 张的组合，受选择上限和强制选牌约束。计分顺序沿用手牌排列；
不枚举排列。默认 8 张手牌有 218 个组合。按选牌数量从大到小惰性枚举，
每次调用完整评分全部组合，只保留当前最佳 15 个，避免存储全部搜索空间。
启动、加载和计分共用调用方 deadline，没有单独的 1 秒或 2.5 秒搜索限制。

全部组合评分完成后按分数降序返回前 15 个组合，同一牌型可以有多个候选。
同分时优先使用更少的牌，再按索引字典序排列；组合不足 15 个时返回全部。
行首为可传给 `play.cards` 的零基索引：

```json
"plays": [
  "0 2 3 5 6: Flush 1240",
  "0 1 2 3 4: Straight 480 minimal",
  "1 4 7: Three of a Kind 420",
  "2 3: Pair 0 not allowed"
]
```

- `minimal`：排除随机奖励、Misprint 取下限。仅实际触发这些计算的候选在结果末尾追加
  `minimal`，没有触发的确定性候选不加标记，不再显示 `random` 后缀。即使概率加成超过
  100%，奖励仍按不触发处理；这是无随机奖励策略，不是所有可能结果的数学最小值。
- `not allowed`：Boss 禁止该出牌，得分为 0。
- `unavailable`：缺少运行环境、隐藏信息、状态变化、不支持的效果、超时或取消。
  任何未完成的枚举都不输出部分候选。

每个枚举只计算这一手的分数：在原版牌背最终修正后停止，跳过销毁与 after-hand 结算。
DNA 和消耗牌创建在效果派发边界屏蔽，不构造假卡，不改变牌组统计。
保留会影响本手分数的变化：成长、强化顺序、重触发、持牌效果，以及 The Tooth/The Ox
的金钱变化。每次试算后恢复同一局面，候选之间不积累副作用。
已知随机奖励明确不触发；未知计分随机调用与 The Hook 的出牌前随机弃牌仍显式不可用。
当前使用原版 1.0.1o 计分，不模拟 Steamodded 或其他 mod 自定义规则。

## revision 与动作语义

内部快照参与 bridge 指纹，因此评分依赖变化会使旧 revision 失效。
服务端每次观察重新完整枚举，不缓存推荐；计算完成后重新读取实机 revision。
变化时丢弃评分，提示重新观察。内部快照不会进入模型观察、工具追踪结果或操作检查输出。

动作前置观察和 `game_operation` 不启动 worker。评分失败仅影响建议字段，
不把已确认完成的动作变成不确定，也不自动重放动作。每个后端持有一个按需启动的 VM，
正常搜索结束后继续复用；后端关闭、进程失败、执行中取消或超时才关闭。
每次请求的 deadline 包括排队和搜索；排队取消不打断前一个请求。请求结束后移除取消
监听，因此旧请求的 signal 不会终止下一次搜索。跨请求持久化的是 VM，不是试算后的牌局。

## 验证

Lua 测试验证只读导出、隐藏信息、抽牌顺序剥离和评分依赖的 revision。
原版无头测试将已经应用被动效果的局面导出，再交给独立 worker，比较两边计分结果。
TypeScript 测试覆盖完整组合枚举、全局前 15 个候选、强制选牌、同分排序、最低奖励策略、
同手成长与副作用隔离、跨观察 VM 复用、排队及执行中取消、过期结果丢弃、动作恢复和快照过滤。
实机验证仍需更新 Mod、重启游戏/MCP 后进行；离线测试不构成实机计分一致性证明。
